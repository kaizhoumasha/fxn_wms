# 设计文档审计器 (Design Document Auditor)

对已完成的设计文档进行审计，确保与需求文档的一致性和内部逻辑的完整性。

## 使用方法

```
/audit-design <设计文档路径>
```

**示例**:
```
/audit-design docs/design/3.2.2-iqc-routing-review.md
```

---

## 审计要求

### 1. 与 user_requirement.md 的对照审计

对照 `user_requirement.md` 中对应章节，检查：

#### 1.1 功能完整性
- 列出 user_requirement.md 中的所有步骤
- 逐一确认设计文档是否覆盖
- 标注缺失的功能

#### 1.2 流程一致性
- 对比业务流程顺序
- 确认参与方一致（WMS/RCS/人工等）
- 确认数据流向一致

#### 1.3 硬件使用一致性
- 对比硬件清单
- 确认 PDA、打印机、电脑的使用场景一致

## 执行步骤

请按以下步骤进行审计：

### 步骤 1: 读取文档
- 读取指定的设计文档
- 识别设计文档对应的 SRS 章节
- 读取 `@docs/SRS.md` 中对应章节
- 读取 `@docs/user_requirement.md` 中相关需求

### 步骤 2: 需求对照审计
- 提取 user_requirement.md 中的所有步骤
- 逐一检查设计文档是否覆盖
- 生成需求覆盖清单
- 计算覆盖率
- 识别缺失功能
- 检查一致性
- 识别设计增强项

### 步骤 3: 内部一致性审计
- 检查角色与职责一致性
- 检查时序图与流程一致性
- 检查功能页面与流程一致性
- 检查数据模型与流程一致性

### 步骤 4: 生成审计报告
- 总体评估
- 设计质量评估
- 问题与建议
- 输出完整的审计报告

### 步骤 5: 更新设计文档
如果设计文档中没有审计报告章节，将审计报告追加到设计文档末尾（在总结章节之前）。
