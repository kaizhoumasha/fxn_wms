## 概述 (Overview)

本文档基于 `3.3.2 混合入库策略` 详细设计文档，将功能需求分解为可执行的 Epic 和 User Story，并提供故事点估算、团队速率计算和迭代计划。

### 团队分工

**团队配置**:
- **WMS 团队** (内部): 2人，负责 WMS 操作员界面、WMS-WES 集成接口、RCS 调度封装
- **WES 团队** (内部): 2人，负责混合入库决策引擎、满箱交换协调、零散入库协调、异常处理、监控仪表板
- **硬件供应商** (外部): 负责 ECS/CTU/RCS 执行层，提供设备接口和物理控制

**职责划分**:
- **WMS 团队**: 库存主数据管理、账务更新、RCS 调度、人工兜底流程、操作员界面
- **WES 团队**: 混合入库决策、任务生成、设备协调、状态追踪、异常处理、监控仪表板
- **硬件供应商**: 流水线控制、料箱/料盘识别、投放/拣选执行、满箱交换执行、结果上报

### 估算方法

**故事点估算**: 使用标准 Fibonacci 序列 (1, 2, 3, 5, 8, 13, 21) 进行故事点估算

**团队速率计算** (基于 2 人团队，2 周迭代):
- **可用工时**: 2人 × 10天 × 8小时/天 = 160 人时
- **有效工时**: 160 × 65% = 104 人时 (考虑会议、代码审查等)
- **综合工时系数**: 3.0 (开发 2.0 + 测试 0.5 + 集成 0.5)
- **团队速率**: 104 ÷ 3.0 ≈ **35 故事点/迭代**

## Epic 1: 混合入库决策引擎 (Hybrid Inbound Decision Engine)

**负责团队**: WES 团队
**总故事点**: 15
**优先级**: P0
**依赖**: Epic 7 (数据库模型与基础设施)

**Epic 描述**: 实现混合入库策略的核心决策引擎，根据料箱存储容量自动判断满箱交换或零散入库模式，查询五层货架空箱资源，生成混合入库任务列表并按优先级排序。

**业务价值**: 自动化入库决策，提升入库效率，减少人工干预，支持满箱交换和零散入库的混合模式。

### 用户故事 (User Stories)

#### US-E1-01: 料箱容量分析算法

**作为** WES 系统
**我想要** 分析单层货架上所有料箱的存储容量
**以便** 自动判断每个料箱应该执行满箱交换还是零散入库

**验收标准** (Acceptance Criteria):
- [ ] 能够查询单层货架上所有料箱的存储状态（已用深度、总深度）
- [ ] 正确计算料箱存储容量: `Usage = (已用深度 / 总深度) × 100%`
- [ ] 能够根据阈值分类料箱：满箱 (≥80%)、优先交换 (50-80%)、零散 (<50%)
- [ ] 支持配置化阈值参数（FULL_EXCHANGE_THRESHOLD, PRIORITY_EXCHANGE_THRESHOLD）
- [ ] 处理边界情况：空料箱、满料箱、无效数据
- [ ] 记录分析结果到日志，包含料箱ID、容量、分类
- [ ] 性能要求：单个货架分析时间 < 500ms

**技术要点**:
- Python 算法实现，使用 SQLModel 查询料箱数据
- 配置参数从 settings.py 读取
- 日志记录使用 structlog
- 单元测试覆盖所有分类场景

**详细设计参考**: [@docs/design/3.3.2-hybrid-inbound-strategy.md §6.1 混合入库决策流程](../docs/design/3.3.2-hybrid-inbound-strategy.md#61-混合入库决策流程-hybrid-inbound-decision-flow)

**故事点**: **3**
**估算理由**: 中等复杂度，涉及数据查询、算法计算、分类逻辑，但业务规则清晰

---

#### US-E1-02: 空箱资源查询服务

**作为** WES 系统
**我想要** 查询五层货架上的空料箱资源
**以便** 为满箱交换任务分配目标空箱

**验收标准** (Acceptance Criteria):
- [ ] 能够调用 WMS API 查询空箱资源: `GET /api/wms/inventory/query?rack_type=five_layer&status=empty`
- [ ] 正确解析 WMS 返回的空箱列表（包含货架ID、A/B面、层号、料箱位置）
- [ ] 支持超时重试机制（3次重试，10s超时）
- [ ] 处理 WMS API 异常情况（超时、网络错误、数据格式错误）
- [ ] 缓存空箱资源列表到 Redis（TTL 60s）
- [ ] 记录 API 调用日志（请求参数、响应时间、结果）
- [ ] 性能要求：API 调用响应时间 < 2s

**技术要点**:
- 使用 httpx.AsyncClient 调用 WMS API
- 实现指数退避重试策略（1s, 2s, 4s）
- Redis 缓存使用 redis-py
- Pydantic 模型验证 API 响应数据
- 单元测试使用 pytest-mock 模拟 WMS API

**详细设计参考**: [@docs/design/3.3.2-hybrid-inbound-strategy.md §6.1 混合入库决策流程](../docs/design/3.3.2-hybrid-inbound-strategy.md#61-混合入库决策流程-hybrid-inbound-decision-flow), [@docs/design/3.3.2-hybrid-inbound-strategy.md §9.3.1 WES 调用 WMS API](../docs/design/3.3.2-hybrid-inbound-strategy.md#931-wes-调用-wms-api)

**故事点**: **2**
**估算理由**: 简单的 API 调用封装，重试和缓存逻辑标准化

#### US-E1-03: 混合入库任务生成器

**作为** WES 系统
**我想要** 根据料箱分类和空箱资源生成混合入库任务
**以便** 为后续执行流程提供任务列表

**验收标准** (Acceptance Criteria):
- [ ] 能够为满箱料箱生成满箱交换任务（task_type: FULL_EXCHANGE）
- [ ] 能够为零散料箱生成零散入库任务（task_type: PIPELINE_PICKING）
- [ ] 正确分配空箱资源给满箱交换任务（先到先得）
- [ ] 处理空箱资源不足的降级场景（满箱降级为零散入库）
- [ ] 生成任务包含完整数据：source_bin_id, target_bin_id, rack_location, priority
- [ ] 任务状态初始化为 PENDING
- [ ] 记录任务生成日志（任务类型、数量、降级情况）
- [ ] 性能要求：单个货架任务生成时间 < 1s

**技术要点**:
- 使用 SQLModel 创建 hybrid_inbound_tasks 记录
- 实现降级逻辑：空箱不足时自动降级为零散入库
- 任务数据模型使用 Pydantic BaseModel
- 事务处理确保任务生成的原子性
- 单元测试覆盖正常流程和降级场景

**详细设计参考**: [@docs/design/3.3.2-hybrid-inbound-strategy.md §6.1 混合入库决策流程](../docs/design/3.3.2-hybrid-inbound-strategy.md#61-混合入库决策流程-hybrid-inbound-decision-flow), [@docs/design/3.3.2-hybrid-inbound-strategy.md §8.1 核心数据表](../docs/design/3.3.2-hybrid-inbound-strategy.md#81-核心数据表-core-tables)

**故事点**: **5**
**估算理由**: 复杂业务逻辑，涉及多种任务类型、降级处理、数据库事务

#### US-E1-04: 任务优先级排序引擎

**作为** WES 系统
**我想要** 对生成的混合入库任务按优先级排序
**以便** 优先处理满箱交换任务和高容量料箱

**验收标准** (Acceptance Criteria):
- [ ] 满箱交换任务优先级高于零散入库任务
- [ ] 同类任务按料箱容量降序排列（容量高的优先）
- [ ] 支持手动调整任务优先级（P1/P2/P3）
- [ ] 排序算法稳定，相同优先级保持原有顺序
- [ ] 排序结果持久化到数据库（priority 字段）
- [ ] 记录排序日志（排序前后任务顺序）
- [ ] 性能要求：排序时间 < 100ms（100个任务）

**技术要点**:
- Python 排序算法，使用 sorted() 和 lambda 表达式
- 优先级规则：priority 值越小优先级越高（P1 > P2 > P3）
- 数据库批量更新 priority 字段
- 单元测试覆盖各种排序场景

**详细设计参考**: [@docs/design/3.3.2-hybrid-inbound-strategy.md §6.1 混合入库决策流程](../docs/design/3.3.2-hybrid-inbound-strategy.md#61-混合入库决策流程-hybrid-inbound-decision-flow)

**故事点**: **3**
**估算理由**: 中等复杂度，排序逻辑清晰，但需要考虑多种优先级规则

#### US-E1-05: 决策配置管理

**作为** 系统管理员
**我想要** 配置混合入库决策的阈值参数
**以便** 根据实际业务需求调整决策策略

**验收标准** (Acceptance Criteria):
- [ ] 支持配置满箱交换阈值（FULL_EXCHANGE_THRESHOLD，默认 80%）
- [ ] 支持配置优先交换阈值（PRIORITY_EXCHANGE_THRESHOLD，默认 50%）
- [ ] 支持配置零散入库阈值（PIPELINE_PICKING_THRESHOLD，默认 50%）
- [ ] 支持配置最大并发货架数量（MAX_CONCURRENT_RACKS，默认 1）
- [ ] 配置参数从环境变量或配置文件读取
- [ ] 配置变更后无需重启服务（热加载）
- [ ] 记录配置变更日志（变更时间、变更人、变更内容）

**技术要点**:
- 使用 pydantic-settings 管理配置
- 配置文件格式：YAML 或 .env
- 热加载使用 watchdog 监听配置文件变更
- 配置验证：阈值范围 0-100%，并发数 ≥1
- 单元测试覆盖配置加载和验证

**详细设计参考**: [@docs/design/3.3.2-hybrid-inbound-strategy.md §4.2 配置参数](../docs/design/3.3.2-hybrid-inbound-strategy.md#42-配置参数)

## Epic 2: 满箱交换协调器 (Full Exchange Coordinator)

**负责团队**: WES 团队
**总故事点**: 21
**优先级**: P0

- **有效工时**: 160 × 65% = 104 人时
- **综合工时系数**: 3.0 (开发 2.0 + 测试 0.5 + 集成 0.5)

## 验收标准总览 (Overall Acceptance Criteria)

### 功能完整性

- [ ] 混合入库决策引擎能够根据容量阈值自动判断满箱交换或零散入库

- [ ] 空货架回收流程能够自动触发并执行
- [ ] 异常处理机制能够检测、分类、处理各类异常
- [ ] 监控仪表板能够实时展示任务状态、流水线状态、设备健康度
- [ ] WMS 操作员界面能够支持手动/自动叫料

- [ ] 单元测试覆盖率 ≥ 80%
