## 概述 (Overview)

### 功能描述

IQC 动态路由与复判系统是 WMS 的核心质量管理模块,负责从收货暂存区到 IQC 检验、复判、路由分发的完整业务流程。系统采用**拉动式 (Pull)** 工作流设计,由 IQC 人员根据工作负荷和优先级主动呼叫送检,避免 IQC 待检区拥堵。

**关键特性**:
- QMS 集成: 抽检策略查询、检验结果获取
- 人工触发机制: 检验完成和复判完成需人工确认
- 多 GRN 栈板支持: 支持混托场景,一个栈板包含多个 GRN
- 实时状态更新: SignalR 实现 Web 界面实时同步
- 完整追溯: PKG 六合一码全程追溯

### 团队分工

**WMS 团队** (内部 - 2 人):
- **职责**: 全权负责 IQC 阶段的所有业务逻辑和流程控制
- **技术栈**: Blazor Server (前后端统一), ASP.NET Core, Entity Framework Core
- **交付物**:
  - 3 个 Web 界面 (待送检列表、优先级调整、检验完成确认)
  - 4 个 PDA 界面 (取样记录、归还记录、拆板作业、复判完成)
  - QMS 集成服务
  - RCS 调度服务
  - 数据库 schema 和迁移脚本

**QMS 团队** (外部):
- **职责**: 提供抽检策略和检验结果查询接口
- **交付物**: API 契约定义、测试环境、Mock 数据

**RCS 团队** (外部):
- **职责**: 提供 AGV 搬运任务调度接口
- **交付物**: Transport API 文档、测试环境

**硬件供应商** (外部):
- **职责**: 提供 PDA 设备规格和测试支持
- **交付物**: PDA 设备、驱动程序、技术支持

### 估算方法

使用标准 Fibonacci 序列 (1, 2, 3, 5, 8, 13, 21) 进行故事点估算:
- **1 点**: 极简单 (单一 CRUD,无业务逻辑)
- **2 点**: 简单 (基础表单,简单验证)
- **3 点**: 中等 (多步骤流程,中等验证)
- **5 点**: 复杂 (复杂业务规则,多集成点)
- **8 点**: 很复杂 (复杂工作流,状态机)
- **13 点**: 史诗级 (应拆分为多个故事)

- 抽检策略查询: `POST /api/qms/sampling/query`

- 创建搬运任务: `POST /api/rcs/transport/create`
- 查询任务状态: `GET /api/rcs/transport/status/{taskId}`

- PDA 仅连接 WMS,通过 Blazor Server SignalR 通信
- 无需额外 API,使用统一的 Blazor 组件

## Epic 1: QMS 集成与抽检策略

**负责团队**: WMS
**总故事点**: 21
**优先级**: P0 (关键路径)
**依赖**: 无

**Epic 描述**:
建立 WMS 与 QMS 系统的集成接口,实现抽检策略查询和待送检任务管理。采用拉动式工作流设计,由 IQC 人员主动呼叫送检,避免 IQC 待检区拥堵。

### 用户故事 (User Stories)

#### US-E1-01: QMS 抽检策略 API 集成

**作为** WMS 系统
**我想要** 调用 QMS 接口查询抽检策略
**以便** 根据物料、供应商、数量等因素确定抽检量

**验收标准** (Acceptance Criteria):
- [ ] 实现 QMS API 客户端,支持 HTTP/REST 调用
- [ ] 推送 GRN 数据给 QMS: `POST /api/qms/sampling/query`
- [ ] 接收 QMS 返回的抽检量和抽检类型
- [ ] 实现重试机制: 3 次重试,10 秒超时
- [ ] 实现错误处理: 网络异常、超时、QMS 返回错误
- [ ] 记录 API 调用日志: 请求参数、响应结果、耗时
- [ ] 支持幂等性: 使用 `grn_number` 作为幂等键
- [ ] 单元测试覆盖率 ≥ 80%

**技术要点**:
- ASP.NET Core HttpClient with Polly (重试策略)
- 配置化 QMS API 地址: `appsettings.json`
- 结构化日志: Serilog
- 异常处理: 自定义 `QmsIntegrationException`

**详细设计参考**: [@docs/design/3.2.2-iqc-routing-review.md §3.1 QMS 抽检策略查询](../docs/design/3.2.2-iqc-routing-review.md#1-qms-抽检策略查询-sampling-strategy-query--owner-wms--qms)

**故事点**: **5**
**估算理由**: 外部系统集成,需要处理网络异常、重试、超时等复杂场景

---

#### US-E1-02: 抽检策略业务逻辑

**作为** WMS 系统
**我想要** 根据 QMS 返回的抽检量生成 IQC 送检任务
**以便** 管理需要检验的 GRN 列表

**验收标准** (Acceptance Criteria):
- [ ] 接收 QMS 抽检量后,生成待送检任务记录
- [ ] 若 `sampling_qty > 0`,创建 `Pending_Inspection_Task` 记录
- [ ] 若 `sampling_qty = 0`,标记 GRN 为免检,直接进入装箱流程
- [ ] 设置默认优先级为 5
- [ ] 任务状态初始化为 `PENDING_CALL`
- [ ] 查询 GRN 分布的栈板列表 (位置、数量)
- [ ] 记录任务创建时间和创建人
- [ ] 单元测试覆盖免检和需检两种场景

**技术要点**:
- Entity Framework Core: `PendingInspectionTask` 实体
- 业务服务: `IqcInspectionService`
- 状态枚举: `InspectionStatus` (PENDING_CALL, IN_TRANSIT, AT_IQC_AREA, etc.)
- 数据库事务: 确保任务创建和 GRN 状态更新的原子性

**详细设计参考**: [@docs/design/3.2.2-iqc-routing-review.md §3.2 IQC 待送检列表生成](../docs/design/3.2.2-iqc-routing-review.md#2-iqc-待送检列表生成-iqc-pending-inspection-list--owner-wms)

**故事点**: **3**
**估算理由**: 中等复杂度的业务逻辑,涉及数据库操作和状态管理

**作为** IQC 人员
**我想要** 查看待送检 GRN 列表
**以便** 了解当前需要检验的物料情况

**验收标准** (Acceptance Criteria):
- [ ] 查询所有 `PENDING_CALL` 状态的待送检任务
- [ ] 按优先级降序、创建时间升序排序

**以便** 根据工作负荷和优先级灵活安排检验任务

**验收标准** (Acceptance Criteria):
- [ ] 支持单选或多选 GRN 进行呼叫
- [ ] 点击"呼叫送检"后,弹出栈板选择对话框

- [ ] 更新任务状态为 `IN_TRANSIT`

**详细设计参考**: [@docs/design/3.2.2-iqc-routing-review.md §3.2.1 IQC 人员呼叫送检](../docs/design/3.2.2-iqc-routing-review.md#21-iqc-人员呼叫送检-iqc-call-for-inspection--owner-wms-web--iqc-人员)

#### US-E2-03: IQC 归还记录 (PDA)

**作为** IQC 作业员
**我想要** 使用 PDA 记录样品归还
**以便** 确保样品回归原栈板

**验收标准**:
- [ ] PDA 扫描 PKG 六合一码
- [ ] 查询取样记录,获取原栈板号

**技术要点**:
- Blazor Server PDA 组件: `IqcReturnScreen.razor`
- 查询服务: `SamplingQueryService`
- 状态更新: `SamplingRecord.Status = RETURNED`

**详细设计参考**: [@docs/design/3.2.2-iqc-routing-review.md §3.5 IQC 归还记录](../docs/design/3.2.2-iqc-routing-review.md#5-iqc-归还记录-return-record--owner-wms-pda), [@docs/design/3.2.2-iqc-routing-review.md §8.5 IQC 归还记录界面](../docs/design/3.2.2-iqc-routing-review.md#5-iqc-归还记录界面-iqc-return-screen)

#### US-E2-04: IQC 检验完成确认 (人工触发)

**作为** IQC 作业员
**我想要** 确认检验完成并触发路由决策
**以便** 将栈板送往正确的目标区域

**验收标准**:
- [ ] 在 Web 界面或 PDA 选择要完成检验的栈板
- [ ] 查询栈板关联的所有 GRN 及其检验状态 (通过 `PalletGrnBindings` 表)
- [ ] 筛选检验中的 GRN (状态为 `SAMPLING` 或 `INSPECTING`)
- [ ] 校验检验中 GRN 的所有取样记录是否已归还
- [ ] 未归还: 显示错误提示,列出未归还的 GRN
- [ ] 已归还: 批量查询 QMS 获取检验结果
- [ ] QMS 结果未录入: 显示错误提示,列出未录入的 GRN
- [ ] QMS 结果已录入: 根据结果生成路由决策
