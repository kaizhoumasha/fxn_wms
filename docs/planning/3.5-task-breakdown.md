## 1. 概述

### 1.1 任务分解目标

本文档基于 `3.5-special-material-handling.md` 设计文档，将特殊物料处理功能分解为可执行的 Epic 和 User Story，用于指导开发团队的迭代开发工作。

### 1.2 范围说明

**入库场景专项**：当前阶段仅覆盖入库（Inbound）场景的特殊物料处理，包括：
- 5种特殊物料类型：高价值物料、MSD物料、异形物料、PCB物料、机构件物料
- 物料分类识别、路由决策、库位分配、上架执行
- QMS质检集成、RCS任务下发、SAP数据同步
- 异常处理、状态监控、报表追溯

**架构约束**：根据设计文档 §0.1，当前阶段由 **WMS 全权负责**，WES 不参与此阶段的特殊物料处理逻辑。

### 1.3 技术栈

- **后端框架**：ASP.NET WebForms + MVC 5 (.NET Framework 4.8)
- **数据库**：SQL Server 2019
- **PDA端**：Blazor Server
- **集成协议**：HTTP REST (RCS, QMS), 批量同步 (SAP)

#### E1: 物料分类与路由决策 (14 点)

**Epic 描述**：
实现物料到货时的自动分类识别和路由决策功能，支持5种特殊物料类型（HIGH_VALUE, MSD, IRREGULAR, PCB, STRUCTURAL）的识别和路由规则引擎。

**业务价值**：
- 自动化物料分类，减少人工判断错误
- 智能路由决策，提升入库效率
- 为后续特殊物料处理流程提供基础数据

##### US-E1-01: 物料类型识别

**故事点**：3
**优先级**：P0
**依赖**：E6-01 (material_extension 表创建)

**用户故事**：
作为 WMS 系统，我需要在物料到货时自动识别其特殊物料类型，以便后续进行差异化处理。

**验收标准**：
1. 系统读取物料主数据（material 表），识别 special_material_type 字段
2. 支持5种类型识别：HIGH_VALUE（高价值）、MSD（湿敏）、IRREGULAR（异形）、PCB、STRUCTURAL（机构件）
3. 分类结果存储至 material_extension 表的 special_material_type 字段
4. 对于未标记的物料，默认为普通物料（NORMAL）
5. 分类结果记录至 special_material_log 表，包含时间戳和操作人

**技术实现要点**：
- 在 `MaterialService.cs` 中新增 `IdentifyMaterialType(string materialCode)` 方法
- 查询 material 表的 special_material_type 字段
- 若为空，检查物料描述关键词（如"PCB"、"MSD"等）进行智能识别
- 更新 material_extension 表
- 记录日志至 special_material_log

**测试用例**：
- TC-E1-01-01: 已标记高价值物料，验证识别结果为 HIGH_VALUE
- TC-E1-01-02: 未标记物料但描述包含"MSD"，验证智能识别为 MSD
- TC-E1-01-03: 普通物料，验证识别结果为 NORMAL
- TC-E1-01-04: 验证日志记录完整性

##### US-E1-02: 路由规则引擎实现

**故事点**：5
**优先级**：P0
**依赖**：E6-02 (routing_rule 表创建)

**用户故事**：
作为 WMS 系统，我需要一个路由规则引擎来根据物料类型、目标区域和存储要求决定物料的目标库位类型和处理指令。

**验收标准**：
1. 规则引擎读取 routing_rule 表，支持多条件匹配（物料类型 + 目标区域 + 存储要求）
2. 规则优先级机制：按 priority 字段降序匹配，返回第一条匹配规则
3. 返回目标库位类型（location_type）和处理指令（handling_instructions）
4. 支持规则的启用/禁用（is_active 字段）
5. 规则匹配失败时，返回默认规则或抛出异常

**技术实现要点**：
- 在 `RoutingService.cs` 中新增 `EvaluateRoutingRule(MaterialRoutingContext context)` 方法
- MaterialRoutingContext 包含：materialType, targetZone, storageRequirements
- 使用 LINQ 查询 routing_rule 表，按 priority DESC 排序
- 实现规则匹配逻辑：支持精确匹配和通配符（如 "*" 表示任意）
- 缓存规则表数据（使用 MemoryCache，5分钟过期）

**测试用例**：
- TC-E1-02-01: 高价值物料 + IQC区域，验证路由至高价值专区
- TC-E1-02-02: MSD物料 + 存储区域，验证路由至湿度控制区
- TC-E1-02-03: 多条规则匹配，验证优先级机制
- TC-E1-02-04: 无匹配规则，验证默认规则或异常处理
- TC-E1-02-05: 禁用规则不参与匹配

**验收标准**：
1. 提供 REST API 端点：`POST /api/routing/decide`
2. 请求参数：materialCode, targetZone, storageRequirements (可选)
3. 响应数据：locationType, locationRecommendations (推荐库位列表), handlingInstructions
4. API 响应时间 < 500ms (P95)
5. 支持批量查询：`POST /api/routing/decide-batch` (最多100条)

**技术实现要点**：
- 在 `Controllers/RoutingController.cs` 中新增 `DecideRouting` 和 `DecideRoutingBatch` 方法
- 调用 RoutingService.EvaluateRoutingRule
- 调用 LocationService.GetRecommendedLocations 获取推荐库位
- 返回 JSON 格式：
  ```json
  {
    "materialCode": "MAT001",
    "locationType": "HIGH_VALUE_ZONE",
    "locationRecommendations": ["HV-A-01-01", "HV-A-01-02"],
    "handlingInstructions": "需QMS质检后上架"
  }
  ```

##### US-E2-01: 高价值物料流程

**故事点**：8
**优先级**：P0
**依赖**：US-E1-02

**用户故事**：
作为仓库管理员，我需要对高价值物料实施专属区域存储、强制质检和全程追溯，以降低损失风险。

**验收标准**：
1. 高价值物料自动路由至高价值专区（HIGH_VALUE_ZONE）
2. 强制QMS质检流程：到货后自动创建质检任务，质检通过后才能上架
3. 安全追溯：记录所有操作日志（到货、质检、上架、出库）至 special_material_log
4. 库位限制：高价值专区仅允许存放高价值物料
5. 异常告警：质检超时（>24小时）自动发送告警

**技术实现要点**：
- 在 `HighValueMaterialHandler.cs` 中实现处理逻辑
- 到货时调用 QMS API 创建质检任务：
  ```csharp
  var qmsTask = await _qmsClient.CreateInspectionTask(new {
      materialCode = material.Code,
      palletId = pallet.Id,
      inspectionType = "HIGH_VALUE",
      priority = "HIGH"
  });
  ```
- 监听 QMS Webhook 接收质检结果（见 US-E2-06）
- 质检通过后更新物料状态为 AVAILABLE，触发上架流程
- 质检不通过，路由至复判区或退货区
- 使用 Hangfire 定时任务检查质检超时（每小时执行）

**测试用例**：
- TC-E2-01-01: 高价值物料到货，验证路由至高价值专区
- TC-E2-01-02: 验证QMS质检任务创建成功
- TC-E2-01-03: 质检通过，验证物料状态更新为 AVAILABLE
- TC-E2-01-04: 质检不通过，验证路由至复判区
- TC-E2-01-05: 质检超时24小时，验证告警发送
- TC-E2-01-06: 验证所有操作记录至日志表

##### US-E2-02: MSD物料流程

**故事点**：8
**优先级**：P0
**依赖**：US-E1-02

**用户故事**：
作为仓库管理员，我需要对MSD物料实施湿度控制区存储、烘烤时间追踪和有效期管理，以确保物料质量。

**验收标准**：
1. MSD物料根据等级（2a/3/4/5a）路由至对应湿度控制区
2. 烘烤时间追踪：记录开封时间（floor_life_start_time）、车间暴露时间（floor_life_hours）
3. 有效期管理：根据MSD等级计算有效期，超期自动标记为 EXPIRED
4. 烘烤提醒：车间暴露时间达到80%时发送提醒
5. 存储环境监控：集成温湿度传感器数据（预留接口）

**技术实现要点**：
- 在 `MsdMaterialHandler.cs` 中实现处理逻辑
- MSD等级与车间暴露时间映射（参考IPC/JEDEC标准）：
  ```csharp
  var floorLifeHours = msdLevel switch {
      "2a" => 4,
      "3" => 168,
      "4" => 72,
      "5a" => 24,
      _ => throw new ArgumentException("Invalid MSD level")
  };
  ```
- 在 material_extension 表中新增字段：
  - floor_life_start_time (开封时间)
  - floor_life_hours (允许暴露时间)
  - baking_required (是否需要烘烤)
- 使用 Hangfire 定时任务检查有效期（每小时执行）
- 发送提醒至 PDA 和管理界面

**测试用例**：
- TC-E2-02-01: MSD 2a物料，验证路由至湿度控制区
- TC-E2-02-02: 开封后，验证 floor_life_start_time 记录
- TC-E2-02-03: 暴露时间达到80%，验证提醒发送
- TC-E2-02-04: 暴露时间超期，验证状态更新为 EXPIRED
- TC-E2-02-05: 不同MSD等级，验证车间暴露时间计算正确

##### US-E2-03: 异形物料流程

**故事点**：5
**优先级**：P0
**依赖**：US-E1-02

**用户故事**：
作为仓库管理员，我需要对异形物料（超大、超重、不规则形状）实施人工处理区存储和特殊库位分配。

**验收标准**：
1. 异形物料自动路由至人工处理区（MANUAL_HANDLING_ZONE）
2. 特殊库位分配：根据物料尺寸（length, width, height）和重量（weight）分配合适库位

**团队组成**：

**速率计算**：
