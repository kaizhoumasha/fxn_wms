### US-E1-01: 装箱任务呼叫界面 (Kitting Task Call Interface)

**故事点 (Story Points)**: 5  
**优先级 (Priority)**: P0  
**依赖 (Dependencies)**: 无  
**设计文档引用 (Design Reference)**: [@docs/design/3.3.1-smt-smart-kitting.md §3.1 装箱任务呼叫](../docs/design/3.3.1-smt-smart-kitting.md#31-装箱任务呼叫-kitting-task-call)

**用户故事 (User Story)**:
作为仓库作业员，我需要在装箱区工业电脑上选择待装箱栈板并呼叫装箱任务，以便启动自动化装箱流程。

**验收标准**:
- [ ] Blazor Server页面，显示收货暂存区的待装箱栈板列表
- [ ] 筛选条件：栈板状态 = "IQC_PASSED" 或 "EXEMPT"
- [ ] 显示栈板信息：栈板号、GRN号、物料编码、数量、料盘尺寸
- [ ] 支持栈板号搜索和选择
- [ ] 根据料盘尺寸自动分配线体（7寸→Line 1优先，13/15寸→Line 2）
- [ ] 生成装箱任务：{ pallet_id, grn_id, material_id, qty, dims }
- [ ] 调用RCS API下发搬运任务（收货暂存区 → 料盘装箱区）
- [ ] 接收RCS返回的task_id和estimated_arrival
- [ ] 更新任务状态为"DISPATCHED"
- [ ] SignalR实时推送任务状态到前端界面
- [ ] 验证栈板是否在收货暂存区
- [ ] 验证装箱区对应线体是否有空间接收栈板
- [ ] RCS调度失败时重试3次，失败后人工介入

**技术要点 (Technical Points)**:
- Blazor Server组件开发
- Entity Framework Core数据访问
- FluentValidation数据验证
- SignalR实时状态更新

- [ ] 定时扫描收货暂存区的待装箱栈板队列（每5分钟）
- [ ] 按栈板到达时间顺序排序
- [ ] 筛选条件：栈板状态 = "IQC_PASSED" 或 "EXEMPT"
- [ ] 根据料盘尺寸自动分配线体（7寸→Line 1优先，13/15寸→Line 2）
- [ ] 验证装箱区对应线体是否有空间接收栈板
- [ ] 生成装箱任务：{ pallet_id, grn_id, material_id, qty, dims }
- [ ] 调用RCS API下发搬运任务（收货暂存区 → 料盘装箱区）
- [ ] 接收RCS返回的task_id和estimated_arrival
- [ ] 更新任务状态为"DISPATCHED"
- [ ] SignalR实时推送任务状态到前端界面
- [ ] RCS调度失败时重试3次，失败后告警
- [ ] 装箱区无空间时暂停派送，等待空间释放

**技术要点 (Technical Points)**:
- 后台服务（Hosted Service）
- 定时任务调度（Quartz.NET）
- HTTP客户端（HttpClient）
- 重试策略（Polly）

### US-E2-03: 智能分箱算法核心 (Intelligent Binning Algorithm Core)

**故事点 (Story Points)**: 8  
**优先级 (Priority)**: P0  
**依赖 (Dependencies)**: US-E2-02  
**设计文档引用 (Design Reference)**: [@docs/design/3.3.1-smt-smart-kitting.md §3.5 智能分箱算法](../docs/design/3.3.1-smt-smart-kitting.md#35-智能分箱算法-intelligent-binning-algorithm)

**用户故事 (User Story)**:  
作为WES系统，我需要实现智能分箱算法，根据物料特性、货架类型、货位状态，计算最优的料盘放置方案，以便最大化货架利用率和拣选效率。

**验收标准**:
- [ ] 实现同物料合并规则：相同物料的料盘优先放入同一货位
- [ ] 实现货位类型匹配：根据料盘尺寸选择合适的货位类型
- [ ] 实现深度优先策略：优先填满已有物料的货位，再开新货位
- [ ] 实现均衡分布策略：避免单层过载，保持货架平衡
- [ ] 接收料盘信息（物料编码、批次号、数量、尺寸）
- [ ] 接收货架信息（类型、层数、列数、当前状态）
- [ ] 接收业务规则（同物料合并、货位容量限制）
- [ ] 输出目标货架ID
- [ ] 输出目标货位（层、列、货位号）
- [ ] 输出放入顺序（多个料盘时）
- [ ] 输出预计填充率
- [ ] 单次计算时间 ≤ 500ms
- [ ] 支持批量计算（一次最多50个料盘）
- [ ] 算法准确率 ≥ 95%（人工评估）

**技术要点 (Technical Points)**:
- 贪心算法/动态规划
- 多目标优化
- 缓存策略（Redis）
- 单元测试覆盖率 ≥ 90%

### US-E2-04: 分箱结果计算 (Binning Result Calculation)

**优先级 (Priority)**: P0

**用户故事 (User Story)**:  
作为WES系统，我需要在接收到料盘扫描结果后，立即调用分箱算法计算放置方案，并预占目标货位，以便指导后续的机械臂放入操作。

**验收标准**:
- [ ] 接收供应商视觉扫描结果
- [ ] 解析料盘号、物料编码、批次号
- [ ] 验证物料合法性（查询WMS主数据）
- [ ] 调用智能分箱算法

- [ ] 预占目标货位（状态：空闲 → 预占）
- [ ] 生成分箱指令（料盘号、目标货架、层、列、货位）
- [ ] 记录分箱决策日志（供审计和优化）

## C. 验收标准总览 (Acceptance Criteria Overview)

### 功能性验收 (Functional Acceptance)
- [ ] WMS能够接收装箱需求并自动派送任务

- [ ] 智能分箱算法计算时间 ≤ 500ms
- [ ] 同物料自动合并到同一货位
- [ ] 满架自动检测并切出

- [ ] 单个装箱任务端到端时间 ≤ 5分钟
- [ ] 系统吞吐量 ≥ 60个料盘/小时
- [ ] API响应时间 ≤ 200ms (P95)
- [ ] 数据库查询时间 ≤ 100ms (P95)
- [ ] 并发任务数 ≥ 10个

### 可靠性验收 (Reliability Acceptance)
- [ ] 系统可用性 ≥ 99.5%
