## 概述 (Overview)

**功能描述**: SMT 生产发料协调系统是一个复杂的自动化物料配送系统,涉及 WMS 任务生成、WES 执行协调、ECS 硬件控制、CTU 批量上料、四识别点位集成、退料流水线错误处理等多个子系统的协同工作。

**核心优化策略**:
- **批量操作优化**: 货架预规划、批量调度、批量上料,预期效率提升 40-60%
- **并行操作**: 退货架间转移与五层货架流水线拣料可并行进行
- **实时库存同步**: 每次拣料完成后立即扣减库存,确保数据实时性

**团队分工**:
- **WMS 团队** (内部): 任务生成、货架规划、批量调度、库存管理、人工兜底流程
- **WES 团队** (内部): 任务队列管理、硬件协调、识别点位集成、拣料执行、结果上报
- **硬件供应商** (外部): ECS 设备控制、CTU 批量上料、视觉识别、机械臂操作

**估算方法**: 使用标准 Fibonacci 序列 (1, 2, 3, 5, 8, 13, 21) 进行故事点估算

**总体规模**: 9 个 Epic,共 159 故事点

**团队配置**:
- 团队人数: 2 人
- 生产率: 2 人时/故事点 (纯开发时间)
- 迭代周期: 2 周/Sprint
- 有效工时占比: 65%
- 综合工时系数: 3.0 (开发 + 测试 + 集成)

**团队速率**: 17 故事点/Sprint

**预估工期**: 10 个 Sprint (20 周,约 5 个月)

## Epic 1: WMS 任务生成与货架规划

**负责团队**: WMS 团队
**总故事点**: 19
**优先级**: P0
**依赖**: 无

**Epic 描述**: 实现 WMS 任务生成、货架预规划、物料定位、批量调度等核心功能，为 WES 自动化执行提供基础。核心优化点是货架预规划算法（退料优先 + FIFO）和批量调度，预期减少 AGV 往返次数 60-80%。

### 用户故事 (User Stories)

#### US-E1-01: 货架预规划算法实现

**作为** WMS 系统
**我想要** 实现货架预规划算法（退料优先 + FIFO）
**以便** 在任务开始前识别所有相关货架和料盘位置，减少 AGV 往返次数

**验收标准** (Acceptance Criteria):
- [ ] 实现退料优先逻辑：优先选择退料货架上的物料
- [ ] 实现 FIFO 逻辑：同一物料多个料盘时，按入库时间先进先出
- [ ] 支持跨货架物料识别：一个任务的物料可能分布在多个货架
- [ ] 输出货架清单：包含退料货架和五层货架列表
- [ ] 输出料盘清单：包含 PKG 码、位置、数量信息
- [ ] 处理库存不足场景：部分物料无库存时给出明确提示
- [ ] 性能要求：单个任务规划时间 < 2 秒

**技术要点**:
- C# LINQ 复杂查询（多表关联）
- 退料货架优先级算法
- FIFO 排序逻辑（按入库时间）
- 数据库索引优化（货架、料盒、储位）

**详细设计参考**: [@docs/design/3.3.3-smt-production-issue.md §6.1 WMS 任务生成与下发](../docs/design/3.3.3-smt-production-issue.md#61-wms-任务生成与下发)

**故事点**: **5**
**估算理由**: 复杂业务逻辑，涉及多表关联查询、优先级算法、FIFO 排序，需要性能优化

---

#### US-E1-02: 物料定位识别功能

**作为** WMS 系统
**我想要** 精确定位每种物料的具体料盘位置
**以便** 为 WES 提供准确的拣料指令和位置信息

**验收标准** (Acceptance Criteria):
- [ ] 查询物料所在货架编码
- [ ] 查询物料所在料盒编码
- [ ] 查询物料在料盒内的储位信息
- [ ] 查询料盘 PKG 码（6合1 编码）
- [ ] 查询料盘当前数量
- [ ] 支持同一物料多个料盘的情况
- [ ] 返回料盘叠放高度信息（用于机械臂工作高度计算）
- [ ] 处理料盘不存在或位置异常的情况

**技术要点**:
- SQL Server 多表关联查询
- 库存表、货架表、料盒表、储位表关联
- PKG 码解析逻辑
- 叠放高度计算

**详细设计参考**: [@docs/design/3.3.3-smt-production-issue.md §6.1 WMS 任务生成与下发](../docs/design/3.3.3-smt-production-issue.md#61-wms-任务生成与下发), [@docs/design/3.3.3-smt-production-issue.md §8.1 WMS 数据库表](../docs/design/3.3.3-smt-production-issue.md#81-wes-数据库表postgresql)

**故事点**: **3**
**估算理由**: 中等复杂度的数据库查询，涉及多表关联，但逻辑相对清晰

- [ ] 记录任务接收日志

**技术要点**:

## 团队迭代计划 (Team Sprint Planning)

### 团队速率计算 (Team Velocity Calculation)

**基础参数**:
- 团队人数: 2 人
- 迭代周期: 2 周 = 10 工作日
- 每天工时: 8 小时
- 有效工时占比: 65%（考虑会议、代码审查、沟通等）
- 纯开发生产率: 2 人时/故事点
- 综合工时系数: 3.0（开发 + 测试 + 集成）

**计算过程**:
```
可用工时 = 2 人 × 10 天 × 8 小时/天 = 160 小时
有效工时 = 160 小时 × 65% = 104 小时
综合工时/故事点 = 2 人时 × 3.0 = 6 小时/故事点
团队速率 = 104 小时 ÷ 6 小时/故事点 = 17.3 故事点/Sprint
```

**团队速率**: **17 故事点/Sprint**（取整）

- 可用时间: 10天 × 8小时 = 80小时/Sprint

- 有效工时: 80 × 0.7 = 56小时/Sprint
- 综合时间系数: 1.5 (包含自测、联调、返工)
- 速率: 56 ÷ 1.5 ≈ 37小时 ≈ 7故事点/Sprint

**WES 团队 (1人)**:
- 可用时间: 10天 × 8小时 = 80小时/Sprint
- 有效工作率: 70%
- 有效工时: 80 × 0.7 = 56小时/Sprint
- 综合时间系数: 1.5
- 速率: 56 ÷ 1.5 ≈ 37小时 ≈ 7故事点/Sprint

### E. 整体验收标准

#### 功能性验收 (Functional Acceptance)

1. **货架预规划准确率** ≥ 95%
   - 测试方法: 100 个生产任务，统计货架规划命中率
   - 通过标准: 95 个任务的货架规划无需人工调整

2. **批量装载效率提升** ≥ 40%
   - 基准: 单次装载平均耗时 (现状)
   - 目标: 批量装载平均耗时降低 40% 以上
   - 测试方法: 对比 50 次单次装载 vs 50 次批量装载

3. **四识别点集成成功率** ≥ 98%
   - 测试方法: 1000 次识别操作，统计成功率
   - 通过标准: 失败率 ≤ 2%，且失败后重试成功

4. **CTU 信号协调准确率** = 100%
   - 测试方法: 500 次 CTU 操作，验证信号时序
   - 通过标准: 无信号丢失、无重复执行、无死锁

#### 性能验收 (Performance Acceptance)

1. **任务下发响应时间** ≤ 2秒
   - WMS → WES 任务下发 API 响应时间
   - 测试方法: 并发 10 个任务下发请求

2. **任务调度延迟** ≤ 5秒
   - WES 接收任务到下发 CTU 指令的时间
   - 测试方法: 100 个任务的平均调度延迟

3. **结果回传延迟** ≤ 3秒
   - CTU 完成到 WMS 收到结果的时间
   - 测试方法: 100 个任务的平均回传延迟

4. **系统并发能力** ≥ 20 任务/分钟
   - 测试方法: 压力测试，持续 30 分钟
   - 通过标准: 无任务丢失、无系统崩溃

#### 可靠性验收 (Reliability Acceptance)

1. **异常恢复成功率** ≥ 95%
   - 测试方法: 模拟 100 次异常场景 (设备故障、网络中断、超时)
   - 通过标准: 95 次自动恢复或降级处理成功

2. **数据一致性** = 100%
   - 测试方法: 1000 次操作后，对比 WMS/WES/ECS 数据
   - 通过标准: 无数据不一致、无幽灵库存

3. **系统可用性** ≥ 99.5%
   - 测试方法: 连续运行 7 天，统计故障时间
   - 通过标准: 故障时间 ≤ 50 分钟/周

#### 数据质量验收 (Data Quality Acceptance)

1. **料盘级追溯完整性** = 100%
   - 测试方法: 随机抽查 100 个料盘，验证追溯链
   - 通过标准: 所有料盘可追溯到货架、Bin、PKG

2. **识别点数据准确性** ≥ 99%
   - 测试方法: 对比识别点扫描数据与实际物料
   - 通过标准: 错误率 ≤ 1%

3. **日志完整性** = 100%
   - 测试方法: 验证关键操作日志记录
   - 通过标准: 所有任务状态变更、异常、人工干预均有日志
