## 1. 设计定位与范围 (Design Scope)

### 1.1 设计定位
本文档聚焦于 WES 系统的**高级调度算法**与**全局优化策略**。
WES 的基础执行能力（如任务队列、状态机、设备连接、重试机制、幂等性）由 **3.3.0 WES 核心基础平台** 提供。
具体的业务流程（如装箱算法、发料优先级）由各业务模块（3.3.1/3.3.2/3.3.3）定义。

本模块作为**大脑**，通过分析历史数据和实时状态，生成优化建议或调整任务优先级，注入到 3.3.0 的执行引擎中。

### 1.2 功能范围
1.  **冷热区存储优化 (Hot/Cold Zone Storage Optimization)**: 基于历史频次动态调整物料存放位置。
2.  **全局负载均衡 (Global Load Balancing)**: 在多条产线/区域间平衡任务负载。
3.  **高级任务编排 (Advanced Orchestration)**: 处理复杂的任务依赖链和死锁检测。
4.  **资源预留与冲突解决 (Resource Reservation & Conflict Resolution)**: 解决多任务对同一资源的竞争。

## 2. 核心策略算法 (Core Strategy Algorithms)

### 2.1 冷热区存储优化策略 (Hot/Cold Zone Optimization)

**目标**: 将高频访问物料（热料）移动到易于访问的区域（如五层货架 A 面），低频物料（冷料）移动到深层区域（如 B 面），以提升出入库效率。

**算法逻辑**:

1.  **数据采集**:
    *   WES 每日凌晨 2:00 触发分析任务。
    *   从 `wes_execution_logs` (3.3.0 定义) 聚合过去 7 天和 30 天的出库频次。

2.  **热度分级**:
    ```python
    def calculate_zone_level(material_id):
        count_7d = query_issue_count(material_id, days=7)
        count_30d = query_issue_count(material_id, days=30)

        if count_7d >= CONFIG.HOT_THRESHOLD (e.g. 10):
            return "HOT"
        elif count_30d == 0:
            return "COLD"
        else:
            return "NORMAL"
    ```

3.  **位置评分**:
    *   为每个存储位置定义 `Accessibility_Score` (访问便捷度)。
    *   例如：五层货架 A 面 > B 面；底层 > 高层。

4.  **优化建议生成**:
    *   识别 "热料在冷区" 和 "冷料在热区" 的异常项。
    *   生成 **货架调整任务 (Relocation Task)**，提交给 3.3.0 执行引擎。
    *   **限制**: 每日调整任务数不超过系统容量的 5%（避免影响正常作业）。

### 2.2 动态负载均衡策略 (Dynamic Load Balancing)

**目标**: 在 3.3.0 提供的设备并发控制基础上，实现跨设备/跨区域的智能任务分配。

**算法逻辑**:

1.  **负载评估**:
    *   实时计算各区域/设备的负载指数。
    *   `Load_Index = (Current_Tasks + Queue_Length) / Max_Concurrency`

2.  **动态分配**:
    *   当新任务生成时（如 3.3.1 装箱任务），若存在多条可用流水线（Line 1 / Line 2）。
    *   优先选择 `Load_Index` 最低的资源。

    ```python
    def select_optimal_device(candidate_devices):
        min_load = float('inf')
        selected = None
        for dev in candidate_devices:
            load = get_device_load(dev.id)
            if load < min_load:
                min_load = load
                selected = dev
        return selected
    ```

3.  **拥塞溢出 (Spillover)**:
    *   若首选资源负载 > 0.8 (拥塞阈值)，且备用资源负载 < 0.5，则触发任务重路由。

### 2.3 依赖死锁检测 (Deadlock Detection)

**目标**: 在 3.3.0 的任务执行过程中，监控并解决因资源交叉锁定导致的死锁。

**场景**:
*   任务 A 锁定 货架 1，等待 AGV 2。
*   任务 B 锁定 AGV 2，等待 货架 1。

**检测机制**:
1.  构建 **资源等待图 (Wait-for Graph)**。
2.  周期性（如每 5 分钟）运行 DFS 算法检测环路。
3.  **恢复策略**:
    *   识别环路中优先级最低的任务。
    *   调用 3.3.0 的 `Cancel` 接口取消该任务，释放资源。
    *   触发报警并重新调度该任务。

## 3. 系统集成设计 (System Integration)

### 3.1 与 3.3.0 核心平台的交互

本模块作为**策略插件**运行，不直接控制硬件，而是通过 API 操作 3.3.0。

*   **数据输入**:
    *   监听 3.3.0 的 `Task_Completed` 事件（用于统计频次）。
    *   查询 3.3.0 的 `Device_Status`（用于负载均衡）。
*   **指令输出**:
    *   调用 3.3.0 的 `Create_Task` 接口（提交移库优化任务）。
    *   调用 3.3.0 的 `Cancel_Task` 接口（解决死锁）。

### 3.2 数据库设计 (Database Design)

仅定义策略相关的配置表和日志表，核心任务表复用 3.3.0。

#### 3.2.1 策略配置表 (strategy_config)

| 字段名 | 类型 | 说明 |
|---|---|---|
| config_key | VARCHAR | 配置键 (e.g., 'HOT_THRESHOLD') |
| config_value | VARCHAR | 配置值 (e.g., '10') |
| strategy_type | VARCHAR | 策略类型 (HOT_COLD, LOAD_BALANCE) |
| updated_at | TIMESTAMP | 更新时间 |

#### 3.2.2 优化记录表 (optimization_log)

| 字段名 | 类型 | 说明 |
|---|---|---|
| log_id | BIGINT | 主键 |
| strategy | VARCHAR | 策略名称 |
| action | VARCHAR | 执行动作 (e.g., 'CREATE_RELOCATION') |
| target_id | VARCHAR | 关联对象 (物料/设备ID) |
| details | JSON | 详细参数 (原位置/新位置) |
| timestamp | TIMESTAMP | 时间 |

## 4. 接口设计 (API Design)

### 4.1 策略配置接口

*   `POST /api/strategy/config`
    *   更新冷热区阈值、负载均衡参数。
*   `POST /api/strategy/trigger/hot-cold-analysis`
    *   手动触发一次冷热区分析。

### 4.2 优化报表接口

*   `GET /api/strategy/reports/optimization`
    *   获取最近执行的优化操作记录和效果评估（如移库次数、预计提升效率）。

---

## 5. 异常处理 (Exception Handling)

*   **策略计算超时**: 若分析任务涉及海量数据导致超时，应采用异步后台任务执行，不阻塞主线程。
*   **优化任务失败**: 若 3.3.0 执行移库任务失败（如设备繁忙），策略引擎应标记该建议为“暂缓”，24小时后重试，避免反复提交无效任务。
